# Article check results and actions

This implements [ADR 0001](adr/0001-archive-article-pilot.md) with the owner's source-only PR workflow. PRs and manually dispatched feature checks use report profile `source`, whose mandatory gate is `source`; the stable required CI job remains `Article package`. Feature pushes do not start a duplicate check. The optional full rendering report uses profile `full` and requires `source`, `build`, `output`, `browser`. JSON keeps stable codes and machine states. Human reports and generated descriptions use `schemas/messages.json`, selected solely by the actual head branch suffix. No LLM or external source fetch is required for source validation.

| Code          | Blocking error                                                                                            | Warning or editorial finding                                                             | Unable to complete                                                                     |
| ------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| HM_METADATA   | Missing/invalid schema field, calendar date or language URL                                               | None                                                                                     | Unreadable source blocks the source gate                                               |
| HM_IDENTIFIER | Duplicate article identity, URL, translation identity or displayed figure ID                              | None                                                                                     | Cannot assess an unreadable package                                                    |
| HM_PATH       | Traversal, escaped asset root or unsupported URL                                                          | None                                                                                     | Inaccessible filesystem blocks assessment                                              |
| HM_IMAGE      | Referenced asset has neither local bytes nor a valid external-original inventory entry                    | None                                                                                     | Undecodable reading assets also block publication                                      |
| HM_FIGURE     | Missing caption, alternative text, provenance or image-role inventory                                     | None                                                                                     | An inaccessible asset cannot pass visual verification                                  |
| HM_STRUCTURE  | Missing sections, active/raw media HTML, unsupported Liquid or private operational data                   | None                                                                                     | Unparseable front matter blocks assessment                                             |
| HM_LINK       | Missing internal anchor, footnote or reference definition                                                 | None                                                                                     | Actual rendered anchors additionally require the browser gate                          |
| HM_MATH       | Unbalanced delimiters, unsupported KaTeX syntax or missing math opt-in                                    | A suspected mathematical mistake is separately HM_EDITOR                                 | Missing parser/browser cannot establish a PASS                                         |
| HM_CONTRACT   | Canonical site schema differs from its SHA-256, ID or owning-repository/path lock                         | None                                                                                     | Missing or unreadable schema/lock blocks validation                                    |
| HM_BUILD      | Stock Jekyll returns an error                                                                             | None                                                                                     | Missing tool or stale/unavailable preview is blocking; downstream gates remain not_run |
| HM_OUTPUT     | Broken generated URLs/assets/language/index contracts                                                     | None                                                                                     | Missing build/tool prevents a successful output gate                                   |
| HM_BROWSER    | Failed request/console, missing image/anchor, formula count/render failure or overflow at either viewport | None                                                                                     | Missing browser/preview blocks the gate; it is never silently skipped                  |
| HM_REQUIRED   | Required assessment throws an error                                                                       | not_run identifies each absent downstream gate                                           | Missing, skipped or cancelled mandatory work is incomplete, never PASS                 |
| HM_EXTERNAL   | Never establishes source invalidity                                                                       | External links are left for editorial verification; outages alone are not errors         | No fetch is required for technical success                                             |
| HM_MARKDOWN   | Source formatting drift                                                                                   | Align tracked tables using `python3 tools/markdown_tables.py --write`                    | Source fails until aligned                                                             |
| HM_REVIEW     | Missing or stale editorial decision                                                                       | Use the canonical review record; publication needs matching approval and closed blockers | Source/Jekyll fail unsafe publication                                                  |
| HM_EDITOR     | Never a technical error by itself                                                                         | Source fidelity, OCR, attribution and factual questions require an editor                | An unanswered question remains open after a technical PASS                             |

Every finding includes its source file/line when applicable, a stable code, severity, explanation and action. For example, `HM_IMAGE` names the missing asset and instructs the author to add it or correct its path. Tool diagnostics remain in their original language beneath a localized explanation. Editorial questions use the report language too: imported English questions have exact-source Russian translations in `schemas/editorial-question-messages.json`. New cross-language questions keep a source-bound `localizations` object in their canonical review record. A Russian source report rejects an open English-edition question without a Russian translation; changed wording cannot reuse a stale translation. Machine findings retain the canonical question. Translation never closes a question or grants approval. JSON reports bind the result and declared profile to the checked head SHA. CI retains only JSON/Markdown reports in `article-report-<sha>` for 14 days. Feature CI never creates a site preview, browser screenshot or PDF.

`node scripts/check-articles.mjs --source-only` reports success only when its source gate passes. It does not declare build, output or browser gates passed; its human report states that these checks and PDF generation are deferred until an owner-approved merge to `master`. Reports without a profile retain the historical full-gate contract. Unknown profiles, missing required gates and skipped or cancelled work never establish a pass. The trusted comment job additionally requires the complete `Prototype checks` workflow to succeed, including its source regression `verify` job. It updates one marked bot comment, checks the live head again before writing and rejects older run IDs/attempts. Completed manually dispatched CI runs also update the current open master-targeting PR: the `workflow_run` handler reads trusted default-branch dictionaries and API metadata, never checks out contributor code or executes artifacts, and ignores stale, closed or unrelated heads.

A successful PR report says “Source checks passed; editorial review pending.” Source validation does not prove complete transfer or correct mathematics. Private evidence in ignored local files in the site project records which source fragments, numerical table cells, formulas and image captions were actually compared; remaining manual questions stay explicit. FELab metadata and NAS originals/images are read only. English and fallback language behavior are regression-tested with Russian content.

The guarded master publication workflow always builds the approved Pages site and validates its output. Article/image-only changes use the light source/output path; code, layout, logic and page changes additionally require the complete reference build and browser suite, compared with the last successful deployment. See [publication performance](PUBLICATION_PERFORMANCE.md). Browser checks require native-size images within the 960 × 720 cap and keyboard-accessible table scrolling at 1440, 390 and 320 pixels. PDF generation and its incremental cache are confined to that master publication workflow; see [PDF editions](ARTICLE_PDF.md). PDFs are deployment outputs and never source commits or PR artifacts.
