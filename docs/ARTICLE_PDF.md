# Article PDF editions

Every rendered article has a localized PDF download near its title. Jekyll renders the original Markdown, figures, footnotes and literal dollar formulas once; the existing local KaTeX renderer typesets the same formulas for the screen and PDF. Playwright Chromium then prints this HTML with a dedicated A4 stylesheet. No second editable text, PDF binary or image derivative is committed.

Run `bundle exec jekyll build --trace` followed by `npm run build:pdf`, then run output and browser checks. For a custom destination, run `node scripts/article-pdf.mjs --site-dir <destination>`. The manifest generated by Jekyll supplies the base path, actual article URLs, language and PDF paths; root-domain builds work too. CI and production run this stage before checking local URLs. Published PDFs travel only with the required Pages deployment artifact; CI still uploads only its small text reports.

PDFs use the existing Russian/English journal logos, embedded PT Serif and KaTeX fonts, white paper, copper accents, page numbers, repeated table headers and bounded illustrations. Article text remains selectable; links point to the public website, never the temporary local rendering server. Print-only image downsampling targets roughly 240 dpi at the rendered size. Source image files and screen rendering remain unchanged. The decorative paper grain is omitted to avoid multi-megabyte per-page raster backgrounds.

The manifest only includes documents admitted by the existing publication gate. Ordinary builds cannot export draft PDFs. Explicit review builds retain the review notice. The exporter clears its previous PDF output before every run, preventing a removed or unpublished article from surviving as an orphaned file. Missing pages, failed assets, unrendered formulas, clipped tables/formulas, invalid language/path bindings or a wrong logo fail the export and publication pipeline.

Checks cover RU and EN export, project/root paths, invalid manifest inputs, stale-output removal, PDF signatures and the downloadable link. Visual review uses rendered PDF pages; read-only extraction checks text, page count and link annotations. Native English translation notices are pages, so they do not acquire a misleading English article PDF.
