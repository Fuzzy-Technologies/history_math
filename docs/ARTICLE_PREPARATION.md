# Preparing the next archival article

Follow [ADR 0001](adr/0001-archive-article-pilot.md). Use existing FELab metadata and NAS originals only for reading. This repository owns the schema, templates, checks and prepared article versions for review. Do not create or modify FELab code, branches, targets, Works or cache entries.

See [check conditions and report interpretation](ARTICLE_CHECKS.md) for stable codes, blocking failures and unavailable checks. `scripts/article-pr.mjs` exports the deterministic `articlePrBody` helper used for pilot PR descriptions; it consumes the same local language dictionaries and an actual head's report.

1. Read the repository instructions and inspect the current site branch and user changes. Search approved digests and metadata in the existing FELab runtime through a read-only SQLite connection (`mode=ro`); do not rebuild or update it. Read the complete authoritative `long.txt`, relevant source documents and images from that article's existing NAS directories. Record source hashes, selection rationale and original publication records in ignored `test-results/private/`. Verify image provenance before copying selected publication assets. A digest is only a candidate finder.
2. Assign a stable public ID; the pilot uses `hm-` plus 12 hexadecimal characters from SHA-256 of the historical Work ID. Retain the original Work mapping in the private local evidence here. Preserve it if a folder is renamed. Choose the content `lang` independently from the report language.
3. Fill `templates/article.md`, or start from `templates/minimal-article.md`. Every schema `required` field is mandatory. Optional fields describe only known facts. Add `date` only for an approved website placement, and keep earlier outlet/date in `original_publication`. Keep `status: draft` during preparation.
4. Preserve every author paragraph, note, formula, caption and bibliography item. Promote the original title to the shared H1 and its section titles to H2. Remove only documented operational instructions and move hashtags to metadata. Record each source fragment's handling in the private coverage ledger. Do not silently alter a historical claim, OCR ambiguity or suspected equation. Record questions in `reviews/<id>.json`; document authorized editorial corrections and their sources there. Short notes need no artificial H2. Biographies require the `Персоналии` tag and series.
5. Use explicit `{#section-id}` anchors, `[text](#section-id)` references, kramdown footnotes and ordinary reference definitions. Every cited definition must exist. Use dollar LaTeX; unsupported commands block the gate. Preserve equality and operation order when splitting a long equation. Preserve the original rows and columns when transcribing image tables. Stage new Markdown and run `python3 tools/markdown_tables.py --write`. Figure records supply `id`, `path`, `alt`, `caption`, `source`, `rights_basis`, plus a verified URL/license when known. Insert `{% include article-figure.html id="fig-1" %}`; put no shared HTML in the article.
6. Prepare `site/_articles/<id>.<lang>.md`, copy selected images to `site/assets/images/<id>/`, and write `reviews/<id>.json` with public reconciliation and editor questions. These files are the single editable site derivative. Keep private source paths, byte hashes, fragment mappings and review evidence in ignored `test-results/private/`, not on NAS or in FELab. Verify original source bytes before and after reading/conversion. Original source and image files are never overwritten. Do not maintain another editable article in a staging folder.
7. Create `feature/article-<id>-ru` for Russian reports, `-en` for English, or omit the suffix for English fallback. While infrastructure PR #26 is pending, start each independent article branch at `feature/archive-pilot-en` and target that temporary base; afterward use `develop`. Make review corrections directly in that article's site branch. Do not write them back to the source archive or FELab.
8. Run `npm ci`, `npm test`, and `node scripts/check-articles.mjs`. The latter needs the existing Ruby/Bundler/Jekyll toolchain, Python and Playwright Chromium. `--source-only` is an explicitly partial source check: its report remains incomplete. `--existing-preview --commit <sha> --preview-dir <artifact-dir>` validates a stock CI-built preview after checking its commit manifest. A missing tool is a failed/incomplete check. CI runs the stock Jekyll build; it does not require an LLM.
9. Inspect all 1440, 390 and 320 pixel screenshots and the actual page. Review formulas, table cells, caption/source relations and bibliography against originals. Update private evidence with exactly what was automatically checked, visually compared or left to the editor. Common validator/template changes require all five pilot packages to pass, not only a minimal example.
10. Commit the public Markdown, its selected assets and `reviews/<id>.json` only. Push to site origin and open a PR into `develop`, or temporarily into the infrastructure branch while it is pending. Add `Tim55667757` and `documentation` without replacing existing metadata, then verify both. Use one or two plain sentences about the change, only open editorial questions, and a CI preview link. Keep operational details in the report, not the PR body. The terminal branch suffix controls automatically generated descriptions as well as reports.
11. Verify the actual head SHA's `Article package` run and its JSON/Markdown report, preview and screenshots. A single bot comment links the current run. Successful technical checks still await editorial review. Retarget temporary-base PRs after infrastructure acceptance, rerun CI, and let the owner merge. Publication requires its separate human-controlled `develop` → `master` PR.

To prepare article six, repeat these steps using the site-owned schema and templates. FELab and NAS access remains read-only throughout.

To inspect a PR without publishing it, download its `article-review-<head-sha>` artifact from the linked Actions run and unzip it. From the infrastructure checkout, run `node scripts/serve-review.mjs <unzipped-artifact>/article-preview`. Open `http://127.0.0.1:4173/history_math/ru/articles/<article-id>/` (or the article's actual language path). The helper serves the stock Jekyll output locally with the same base path and assets; stop it with Ctrl+C. For a direct offline read, open the article PDF in `article-pdfs`; no server is needed. Reports and screenshots are next to `article-preview` in the artifact, which is retained for 14 days. Re-run the workflow if it expires.

Before publication, record the real human approval as described in [the content contract](CONTENT.md#editorial-decision). It covers current public text and image bytes and requires closed blocking questions.
