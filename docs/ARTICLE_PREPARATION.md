# Preparing the next archival article

Follow [ADR 0001](adr/0001-archive-article-pilot.md). NAS/FELab owns editorial content; this repository receives exports for review.

1. Inspect both working trees and instructions. Search approved digests and metadata in the local runtime; read the complete authoritative `long.txt` and relevant source documents on NAS. Record source hashes, selection rationale and original publication records privately. Verify image provenance before public export. A digest is only a candidate finder.
2. Assign a stable public ID; the pilot uses `hm-` plus 12 hexadecimal characters from SHA-256 of the historical Work ID. Retain the private mapping in FELab. Preserve it if a folder is renamed. Choose the content `lang` independently from the report language.
3. Fill `templates/article.md`, or start from `templates/minimal-article.md`. Every schema `required` field is mandatory. Optional fields describe only known facts. Add `date` only for an approved website placement, and keep earlier outlet/date in `original_publication`. Keep `status: draft` during preparation.
4. Preserve every author paragraph, note, formula, caption and bibliography item. Promote the original title to the shared H1 and its section titles to H2. Remove only documented operational instructions and move hashtags to metadata. Record each source fragment's handling in the private coverage ledger. Never silently fix a historical claim, OCR ambiguity or suspected equation. Preserve author text and add an `editorial_questions` entry.
5. Use explicit `{#section-id}` anchors, `[text](#section-id)` references, kramdown footnotes and ordinary reference definitions. Every cited definition must exist. Use dollar LaTeX; unsupported commands block the gate. Preserve equality and operation order when splitting a long equation. Keep explicit table coordinates when transcribing image tables. Figure records supply `id`, `path`, `alt`, `caption`, `source`, `rights_basis`, plus a verified URL/license when known. Insert `{% include article-figure.html id="fig-1" %}`; put no shared HTML in the article.
6. Run FELab's `HistoryMathPreparation.Prepare` through its production store and Work lease, registering only the `site_history_math` target. Store private source paths, byte hashes, fragment mappings and review evidence alongside the derived package. Keep public review data in the export allowlist. The operation creates no competing canonical article and verifies source bytes before/after preparation.
7. Create `feature/article-<id>-ru` for Russian reports, `-en` for English, or omit the suffix for English fallback. Export with FELab's `python -m tools.history_math_publication <work> <site-checkout>`. Export is byte-preserving and refuses conflicting public edits. Review corrections in FELab first, then export the derived package again after resolving its reviewed public counterpart; do not edit NAS and Git independently.
8. Run `npm ci`, `npm test`, and `node scripts/check-articles.mjs`. The latter needs the existing Ruby/Bundler/Jekyll toolchain, Python and Playwright Chromium. `--source-only` is an explicitly partial source check: its report remains incomplete. `--existing-preview --commit <sha> --preview-dir <artifact-dir>` validates a stock CI-built preview after checking its commit manifest. A missing tool is a failed/incomplete check. CI runs the stock Jekyll build; it does not require an LLM.
9. Inspect all wide/narrow screenshots and the actual page. Review formulas, table cells, caption/source relations and bibliography against originals. Update private evidence with exactly what was automatically checked, visually compared or left to the editor. Common validator/template changes require all five pilot packages to pass, not only a minimal example.
10. Commit the public Markdown, its selected assets and `reviews/<id>.json` only. Push to site origin and open a PR into `develop`, or temporarily into the infrastructure branch while it is pending. Add `Tim55667757` and `documentation` without replacing existing metadata, then verify both. Describe selection, known publication, transfer, checks, unresolved questions and how to download the review artifact. The terminal branch suffix controls automatically generated descriptions as well as reports.
11. Verify the actual head SHA's `Article package` run and its JSON/Markdown report, preview and screenshots. A single bot comment links the current run. Successful technical checks still await editorial review. Retarget temporary-base PRs after infrastructure acceptance, rerun CI, and let the owner merge. Publication requires its separate human-controlled `develop` → `master` PR.

To prepare article six, repeat these steps using the same schema and operations. No translation, new validator or new editorial content store is needed.
